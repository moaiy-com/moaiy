# Moaiy v1.0.0 Implementation & Architecture Status Summary

## 1. Executive Summary
This document summarizes the engineering state of the Moaiy v1.0.0 milestone (`feature/v1.0-mas-readiness`). The deliverables resolve all architectural bottlenecks from earlier evaluations, introduce streaming process I/O with dual-queue backpressure, best-effort memory clearing, system Keychain integration, a companion CLI tool, and complete Mac App Store (MAS) & Apple Silicon (`arm64`) packaging readiness while preserving macOS App Sandbox security invariants.

## 2. Milestone Deliverables by Sprint

### Sprint 0: Engineering Infrastructure & Invariants
- **`.cursorrules`**: Architectural rules covering macOS App Sandbox resource pairing, non-blocking asynchronous pipe draining with separate I/O queues, and internal buffer zeroization.
- **`AGENTS.md`**: Directory layout, workflow directives, and high-risk engineering boundaries (tracked in git).
- **`specs/` Hierarchy**: Specifications for streaming I/O with backpressure, resilience, Keychain integration, and CLI companion.
- **`.swiftlint.yml` & `scripts/loop-runner.sh`**: Enforces `swiftlint lint --config .swiftlint.yml --strict` across `GPGService.swift`, `GPGError.swift`, `StreamingCryptoPipeline.swift`, `KeychainService.swift`, `SecureMemory.swift`, `TransientFileRegistry.swift`, `Constants.swift`, and `MoaiyCLI/main.swift` (with `force_try`, `force_cast`, and `unused_optional_binding` enabled), runs the 7-suite 64MB streaming/GPG executable harness, and builds both `Debug` and `Release` targets plus `MoaiyTests` under `Xcode 27.1 (27A9275)`.

### Sprint 1: Streaming Pipeline, Staging & Resilience
- **WP-1 (`StreamingCryptoPipeline.swift` & `GPGService.swift`)**:
  - Implemented 256KB chunked streaming I/O with **independent serial queues (`stdinQueue` and `stdoutQueue`)**, **backpressure throttling** (max 8MB in-flight buffer), and **per-chunk `autoreleasepool` + reusable POSIX `read`/`write` buffer** to guarantee bounded memory consumption (<32MB Peak RSS delta on 64MB streams; measured ~9.5–10.4MB).
  - Eliminated process pipe deadlocks by reading standard output and standard error asynchronously via `readabilityHandler` and `pipeGroup` EOF synchronization.
  - Isolated passphrase handling: passphrases are written to a dedicated temporary token file created with `open(O_CREAT | O_EXCL, 0o600)`, passed via `--passphrase-file`, and overwritten with zeros before `unlink`, preventing sensitive secrets from leaking into standard input or plaintext.
  - Handled early child termination, stdin read errors, stdout write errors, normal exit code 15 vs. `SIGTERM` signal cancellation, and `SIGPIPE` safely.
  - Set plaintext output permissions to `0o600` and ciphertext permissions to `0o644`.
  - Hardened `SecureTempStorage.commitStagedFile`:
    - Calculates **net required space** (`max(0, stagedSize - existingDestinationSize)`) and queries volume availability via POSIX `statfs` first (avoiding sandbox `CacheDelete` returning `Some(0)`).
    - **Zero-data-loss in-place overwrite**: Never calls `removeItem(at: destinationURL)` prior to copying. When overwriting an existing file, backs up original bytes to `SecureTempStorage`, opens `destinationURL` with `open(O_WRONLY)` first (failing cleanly before touching original bytes if permissions or sandbox deny access), truncates and streams staged bytes in place with `fsync` (preserving the inode and `NSSavePanel` security scope), and restores from the backup if any mid-stream write error occurs.
    - **Known Overwrite Limitations**:
      1. *Non-atomic in-place overwrite on abnormal crash*: Because App Sandbox only grants access to the user-selected destination file and not its parent directory, `commitStagedFile` overwrites the file in-place (`ftruncate` + stream write + `fsync`) rather than performing a POSIX atomic `rename`. If the process crashes mid-write (e.g., `SIGKILL` or power loss), the destination file may be left truncated, and the rollback backup (`original.bak`) inside `SecureTempStorage` is retained for up to 24 hours (`staleTTL`) before automatic startup cleanup.
      2. *Rollback backup copy & storage media limits*: The rollback backup is a temporary copy of the original file on disk. `SecureTempStorage.removeOperationDirectory` best-effort zero-overwrites (`zeroScrubDirectoryContents` + `fsync`) regular files before unlinking on normal completion or rollback; however, on copy-on-write filesystems (APFS) and wear-leveled SSDs, physical flash blocks cannot be guaranteed erased at the user-space filesystem layer.
  - Directly exposed `encryptFileStreaming` and `decryptFileStreaming` on `GPGService` with full `decryptFile` parity (`--status-fd 2`, loopback passphrase handling, `DECRYPTION_OKAY` verification, and `ensurePreferredDecryptionKey`), and wired them into `KeyActionMenu.swift`.
  - `StreamingProgressReporter` features 10Hz UI throttling.
- **WP-2 (`SecureMemory.swift`, `TransientFileRegistry.swift`)**:
  - `SecureBytes` & `SecureString` provide best-effort internal buffer clearing via Darwin `memset_s` upon deallocation.
  - `TransientFileRegistry` actively tracks directories created by `SecureTempStorage` and hooks into `NSApplication.willTerminateNotification` to purge active scratch directories and run registered exit hooks (`gpgconf --homedir <activeHome> --kill gpg-agent`) on application exit.

### Sprint 2: System Integration & CLI Companion
- **WP-3 (`KeychainService.swift`)**:
  - Integrated Apple Keychain Services with `LocalAuthentication` (`.userPresence`), supporting Touch ID, Apple Watch, and device passcode fallback.
  - Uses `kSecUseDataProtectionKeychain: true` when signed with an Apple Developer certificate (`com.apple.application-identifier`), with controlled fallback to the macOS login Keychain when `errSecMissingEntitlement (-34018)` occurs on unsigned/ad-hoc local builds (`allowLegacyKeychainFallback == true` and `!requireBiometrics`), and never queries the legacy Keychain on `errSecItemNotFound` unless legacy fallback was actively used.
  - Added typed `GPGError.ambiguousKeyReference(String)` in `GPGError.swift` and `GPGService.resolvePrimaryFingerprint(for:)`, replacing string-matching heuristics.
  - Added single-pass `resolvePrimaryFingerprint(for:)` (`GPGService.matchPrimaryFingerprintsInColonOutput`) that runs a single `gpg --list-secret-keys --with-colons --fixed-list-mode` subprocess to resolve 8-char short IDs, 16-char long IDs, 40-char primary fingerprints, and subkey IDs/fingerprints in $O(1)$ process launches, logging warnings via `logger.warning` if key enumeration fails.
  - Preserved `decryptFile` and `decryptFileStreaming` backward compatibility when `preferredSecretKey` is blank or malformed (skipping Keychain pre-lookup rather than failing before GPG runs, while still enforcing `ensurePreferredDecryptionKeyStatic` for valid key references).
- **WP-4 (`MoaiyCLI/main.swift`)**:
  - Standalone `moaiy-cli` companion tool with `signal(SIGPIPE, SIG_IGN)` enabled on startup.
  - Fully implemented subcommands: `status` (with structured GnuPG config parsing for Kyber-768), `list-keys` (supporting `--secret`), `encrypt`, and `decrypt`.
  - Non-blocking concurrent pipe handling to eliminate stdout buffer deadlocks.
  - Auto-discovers Moaiy App's sandboxed container home (`~/Library/Containers/com.moaiy.app/Data/Library/gnupg`), `~/Library/gnupg`, system `~/.gnupg`, or custom `--gpg-home`.
  - Documented non-interactive execution constraints (`--batch`, `--yes`, gpg-agent passphrase requirement) in `--help`.
  - Unified version string: `1.0.0`.

### Sprint 3: Mac App Store (MAS) & `arm64` Packaging Hardening
- **Child Sandbox Inheritance (`GPGHelper.entitlements` & `scripts/sign_embedded_gpg_bundle.sh`)**:
  - Removed redundant `gpg-wks-server` and `gpgtar` binaries from `gpg.bundle` (reducing bundle size to `3.7 MB`).
  - Added `Moaiy/Resources/GPGHelper.entitlements` (`com.apple.security.app-sandbox` + `com.apple.security.inherit`) and an Xcode build phase (`Sign Embedded GPG Bundle for App Sandbox`) + DMG packaging hook (`scripts/sign_embedded_gpg_bundle.sh`) to sign the `.app`-embedded `gpg.bundle` binaries for App Sandbox inheritance while keeping the source-tree `gpg.bundle` runnable by unsandboxed CLI/test runners.
- **Privacy Manifest & Export Compliance (`PrivacyInfo.xcprivacy` & `Info.plist`)**:
  - Declared `NSPrivacyAccessedAPICategoryUserDefaults` (`CA92.1`), `NSPrivacyAccessedAPICategoryDiskSpace` (`E174.1`), and `NSPrivacyAccessedAPICategoryFileTimestamp` (`C617.1`) in `Moaiy/PrivacyInfo.xcprivacy`.
  - Added `ITSAppUsesNonExemptEncryption = true` to `Moaiy/Info.plist`.
- **Pro Placeholder UI Gating (`AppState.swift`, `SettingsView.swift`, `KeyActionMenu.swift`)**:
  - Added `ProRuntime.isProModuleAvailable` so locked Pro placeholder cards and menu items are automatically hidden when `MoaiyProKit` is not linked (satisfying App Store Review Guideline 2.1), while keeping `NoopProModule` contract descriptors intact for `ProContractsTests` and `scripts/check_pro_contracts.py`.
- **Architecture Alignment (`ARCHS = arm64`) & Open-Source Attribution (`THIRD_PARTY_NOTICES.md`)**:
  - Locked `ARCHS = arm64` in `Moaiy.xcodeproj/project.pbxproj` and enforced `arm64` slice verification in `scripts/package_dmg.sh` and `scripts/release/run_release.sh`.
  - Documented all bundled GnuPG 2.5.21 components, licenses, and CLI process isolation in `THIRD_PARTY_NOTICES.md`.
